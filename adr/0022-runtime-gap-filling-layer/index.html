    ADR 0022: A project-owned layer that fills runtime capability gaps

    Date: 2026-11-08 · Status: Accepted (Phase 0 of the plan in TODO.md)

    Context

    ADR 0021 made frameworks selectable, and it exposed the next problem: the runtimes are not equivalent.

    Gap custom google-adk langgraph
    Durable approval continuations through ApprovalStore yes no (ADK-native, in session) no (fails closed)
    Checkpoint / resume through CheckpointStore yes yes (ADK-specific) no
    Session transcript layout Micro-Agent ADK Micro-Agent
    Governance without inheriting the reference runtime n/a partial no

    A definition that pauses for approval on one runtime and denies the tool on another is not runtime-neutral. Reimplementing each gap inside each adapter duplicates security-sensitive logic and lets adapters drift.

    Decision

    Micro-Agents owns the gap-filling semantics once, in a layer between the bootstrap and the framework. An adapter supplies orchestration only. The layer works at boundaries Micro-Agents already controls and never reaches into framework internals.

    Three mechanisms, delivered in later phases:

    1. Governed tools (GovernedTool). Policy, argument validation, idempotent operations, audit, telemetry and the approval gate run at the tool boundary, whichever framework invokes the tool. Frameworks receive wrapped tools and cannot bypass governance. An approval-needing tool raises a neutral ApprovalRequired; the layer persists the request in the ApprovalStore.
    2. Governed model provider (GovernedModelProvider). Retry, fallback, circuit breaker, deadline, usage accounting and redaction wrap the provider SPI, so adapters that use it get identical behavior.
    3. Governance-provided checkpointing. Snapshotting neutral invocation state at tool-round boundaries in the CheckpointStore, and resuming from it, are services of GovernedRuntime (_load_checkpoint, _save_checkpoint, _delete_checkpoint) that an orchestration calls at its own loop boundaries. RuntimeRegistration.provides declares which capabilities a runtime gets this way and capabilities() reports them as provided.

    Amendment (Phase 3): services, not a decorator. The first draft proposed a CheckpointingRuntime wrapper. That cannot work without framework internals: a wrapper sees only requests and responses, so it can neither read the framework's transcript at a tool boundary nor restore it into a fresh run (intercepting the model provider would resume the model's view but lose the turn that the framework persists to the session). Checkpointing therefore follows the same rule as approvals: the base class owns the neutral state and the stores, and the orchestration calls it where its loop has a tool-round boundary. The state is a CheckpointRecord stamped with a schema version (micro_agent.governance.checkpoints); records from before versioning are schema 1, and records written by the Google ADK adapter are refused because they hold ADK session events.

    Reporting. RuntimeCapabilities distinguishes where a capability comes from. A boolean stays true when the capability is effectively available, so supports() and as_dict() are unchanged. A new provided set names the capabilities that exist only because the layer supplies them, and source(name) / sources() return native, provided or none. LangGraph reports checkpointing as provided (Phase 3).

    Uniform guarantees. micro_agent.runtime.guarantees.UNIFORM_GUARANTEES is the single list of behaviors every runtime must show identically. Each entry is covered (it names the conformance cases that prove it) or planned (it names the plan phase that delivers it). A test requires every covered guarantee to point at an existing conformance case and every conformance case to belong to a guarantee, so the list and the suite cannot drift. A capability reported provided must pass the same cases as native.

    Decision on ADK approvals (Phase 2). ADK runs its own tool loop and owns its resumable session, so its approval continuation stays ADK-native. Its tools run through the shared ToolGovernor (policy, validation, idempotency, timeouts, telemetry, audit); only the confirmation handshake is ADK's. The conformance suite proves the approval contract (pause, approve, deny, unknown continuation) on every runtime, so the difference is the storage location, not behavior.

    Model boundary and invocation resilience (Phase 4). Two pieces sit at the points Micro-Agents already controls, so no adapter reaches into framework internals:

    • InvocationGovernor (micro_agent.governance.invocation) applies the declared runtime semantics around one invocation attempt: circuit breaker, deadline, retry with backoff and jitter (never after a side effect or streamed output) and the fallback error policy. It used to live inside the base class and was therefore unavailable to the Google ADK adapter, which now runs its runner through it. Because an ADK attempt appends to the framework's own session, the adapter snapshots the session through ADK's public service API and restores it before a retry, so a retry does not duplicate the user turn.
    • GovernedModelProvider (micro_agent.governance.models) wraps the provider SPI per call: invocation deadline capped by the model timeout, a model.generate span, latency and token telemetry, and streamed deltas. Per-invocation context travels in a ModelCallScope, like ToolCallScope does for tools. The custom loop, the LangGraph node and the ADK BaseLlm bridge all call it and no longer carry copies of this code. The ADK native Gemini path has no provider call to wrap, so its usage is read from the framework's final model events and reported through the same telemetry and the same usage metadata.

    Session portability (Phase 4). The canonical stored layout is the Micro-Agent transcript under the plain session id. The ADK adapter's session service maps ADK events to and from it (runtimes/google_adk/transcript.py) and keeps the native events in the session metadata with a digest of the transcript: a matching digest means ADK wrote last and its events load losslessly, a mismatch means another runtime appended and events are rebuilt from the messages. Records in the previous prefixed ADK layout are migrated on first read. The trade-off is storing the conversation twice for ADK sessions, in exchange for no conversion step when an operator changes runtime.

    Stays framework-native. The layer does not replace what a framework owns by design: ADK's internal session transcript and its native confirmation flow remain available (native approvals become an opt-in for ADK in Phase 2), and the layer does not rewrite how a framework schedules its own steps.

    Rejected alternative

    Reimplementing checkpoints and approvals separately in each adapter (for example LangGraph's checkpointer and interrupts). It fits one framework and leaves the others behind, doubles the security-sensitive code, and makes the guarantees depend on framework internals that change between releases.

    Consequences

    • A definition behaves the same on every runtime for the guaranteed behaviors; differences are reported, not hidden.
    • New adapters opt into the layer instead of re-deriving governance.
    • Checkpoints resume at tool-round boundaries. They cannot resume inside one model call or a streaming response, and the layer says so rather than claim it.
    • Resumed side effects depend on stable operation keys across frameworks; the key derivation is part of the neutral governance core (Phase 1).
    • Phase 1 removes the current LangGraphRuntime → AdkRuntime inheritance by extracting that core.
